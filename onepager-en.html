RedTeam DefTech Hackathon · Ottawa · Strategy Brief

The contest, and how we win it — one page

Buy Canadian is now policy — but no one can verify whether a product is genuinely Canadian-made. We build the missing verification layer: cryptographic provenance for supply chains, with drones as the use case. Working name: TrueNorth.

This is a pure-software project. What we build = a web app + a bit of cryptographic code + a data file. No hardware at any point — no real drone, no real sensors, no real parts. The "drone" in the brief is just a use-case setting in the data — like building a hospital-scheduling system without opening a hospital.

Proposed: a supply-chain provenance verification platform — one dataset, three viewpoints. The brief's four required deliverables map cleanly onto these three rooms; nothing built that the brief did not ask for.

Supplier room

Enter a drone → see the provenance graph, the Canadian-content %, and the verdict. Read a product's whole history at a glance.

Deliverable B + C

Auditor / Red-team room

Inspect the cryptographic trust chain node by node; if anyone forges, it flags red.

Deliverable D
✓Right-sized, not flashy — a hash-linked DAG: change any node and its hash changes, breaking the chain = tamper-evident. A mature, unremarkable technique — but correct, light, buildable in a day.
✗Deliberately no blockchain — a hash chain is enough for tamper-evidence; consensus solves a problem we do not have. Knowing not to reach for it reads as more senior, not less.
03
The demo · Illustrative example

A drone that lands right on the threshold

Why compute a "Canadian percentage" for a drone — the Canadian Armed Forces want genuinely Canadian-made drones, but a drone has dozens of parts from many countries; a maker writing "Made in Canada" on the label is only self-reporting, and can fake it. This system gives the buyer an independently verifiable answer: how Canadian is this drone, really — and does it qualify.

The drone below and every number are an illustrative example — sample data made up to show how the system works. The real challenge data only arrives 72h before the event. It is still just data, never a physical object.

How the 81% is computed — each supplier signs two numbers: what their stage cost, and how much of that was spent in Canada (Canadian materials + Canadian labour). The system rolls the whole chain up → Canadian cost ÷ total cost. This example = $560 ÷ $690 = 81%. Every number carries a cryptographic signature — no one can alter it, and anyone can re-add it to check.
